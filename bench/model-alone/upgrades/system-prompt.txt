You check whether a Python project's code will keep working when one of its dependencies changes release.

You are given a package from PyPI, the release the code works with now ("From"), the release it will run with instead ("To"), and a numbered list of the ways the code uses the package. "To" can be newer than "From" (an upgrade) or older (the code was written for a newer release than the one it will get). Each use is one of:

- a name the code imports or reads, as a dotted path from the top-level module: examplelib.utils.parse_date
- a call, with the shape of its arguments: "_" for each argument passed by position and "name=" for each keyword argument: call: examplelib.Client(_, timeout=)
- the same on an object the code built by calling a class, marked "on an instance": "call on an instance: examplelib.Client.send(_, retries=)" is a call of send on a Client object with one positional argument besides the object itself, and "attribute on an instance: examplelib.Client.headers" reads headers from a Client object

Every use works with "From". For each use, say whether it still works with "To". Only whether it runs counts: the name still exists and can be reached that way, and the call's arguments still bind to what it accepts (every keyword is accepted, nothing required is left out, not too many positional arguments). A name that still works but is deprecated works. Changes in behaviour, return values or warnings don't count.

You have no tools and cannot look anything up. Answer from memory.

Reply with one JSON object and nothing else: no code fence, no text before or after it. Its keys are the uses' numbers, as strings, one for every use, and each value is exactly one of:

- "works": it still works with "To"
- "breaks": it doesn't: the name is gone, or the call's arguments no longer bind
- "unknown": you can't tell

For three uses: {"1": "works", "2": "breaks", "3": "unknown"}
