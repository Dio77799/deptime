## Reading it

- **Fewer false alarms, fewer breaks found.** Against the five tools, working uses flagged fall from 4.5% to 3.5%
  and clean upgrades with a false alarm from 25 to 15, but breaks found fall from 82.2% to 75.0%. As a check on pull
  requests it would still fail about one clean update in ten.
- **Every break it answered, it flagged** (114 of 114); the 38 it misses all have no verdict. It left more without
  one than with the five tools: 765 uses without a verdict (425 in DT-QA-20) and 30 replies that aren't a JSON
  object (16), 9 of them empty.
- **The model mostly couldn't use `check_upgrade` on this format.** It called the tool in 76 of 171 upgrades (83
  calls; first in 45 of them). Replaying each call on the same index: 47 passed code that doesn't parse (the
  question's notation, `mistralai.Mistral(api_key=)`, or uses written as comments), 18 parsed but use no import of
  the package, so nothing was read, and 18 read uses, 3 of them reporting a break. The tool said so in each case
  (`files_unreadable` and a note, or `uses: 0`), and the model went on with the other tools: 350 `symbol_history`
  calls, 287 `check_symbols`.
- **So this doesn't show what a model does with `check_upgrade` on real code,** where it reads the files as they are;
  the protocol listed that as not measured. What it does show: handed uses in this notation, a 9B model doesn't
  turn them into code the tool can read, and still loses most of DepTime's precision by deciding per use itself.
  DepTime's own check (the command, the Action) is the way to get its 0.1%.
- **A gap in the tool's answer:** code that never imports the package reads as no break with `uses: 0` and no note
  (18 calls). DT-CORE-75 adds the note.
