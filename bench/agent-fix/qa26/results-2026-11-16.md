# Does an agent fix an update's breaks better with DepTime? Results (DT-QA-26)

Protocol: `README.md` here. Probe environments that didn't install: none.

## What it says (written after scoring; the tables below are `score.py`'s)

**The bar is missed on its first line only.** Claude Code on Sonnet 5.5 left the code working in 48 of 66 sessions
with the reworked `/deptime:fix-upgrade` (arm B, 72.7%) and in 46 of 66 alone (arm A, 69.7%). B fixed at least as many
sessions as A and had fewer sessions whose fix broke something new (2 against 4), so two of the three conditions are
met; the 80% line is not. Paired by task, B fixed 6 that A didn't and A 4 that B didn't (McNemar's exact p = 0.754): no
real difference in sessions fixed. B fixed more of the confirmed breaks (81.5% against 78.4%), at about half the cost
(median 14 turns against 24, 0.5 minutes against 1.2, half the output tokens), and changed 677 lines nobody asked for
against A's 1,746. DT-QA-05's 16-point loss is gone: the rework did what it was for, and the 80% line now measures
how hard these updates are (A itself fixes 69.7%) more than the hand-off.

**Why B lost the 4 tasks only A fixed** (README.md asks which part: DepTime's answer, the command's instructions, the
shell or the agent):

- **3: the command's instructions.** On langgraph 0.0.24 → 1.2.20 (`prebuilt.create_agent_executor`), llama-index-core
  0.10.44 → 0.14.25 (`ReActAgent.from_tools`) and fastmcp 2.12.0 → 4.1.6 (`resources.ResourceManager`, the tool
  manager), B found the break, by checking DepTime's "can't tell" uses itself on the first two as step 4 asks, and then
  left it, as step 3 says when "the fix isn't clear": explained why and offered a pin. A rewrote the code
  (`create_react_agent`, the workflow `ReActAgent`, fastmcp's providers) and the probe found it works. The leave-it
  rule, not DepTime's answer, lost these.
- **1: DepTime's answer.** On streamlit 1.29.0 → 1.67.0, `st.pyplot()` now needs its figure; `check-upgrade` reported
  no break (required arguments are the held DT-CORE-34), and B, told not to rewrite what DepTime didn't flag, changed
  nothing.

None came from a wrong answer of DepTime's or from the shell. B's 6 wins are mostly where a full list helps: on the two
largest it fixed 37 of 37 and 15 of 15 confirmed breaks, where A fixed 35 and 8.

**The shell.** 35 of B's 66 sessions had a Bash command denied: shell edits (`sed`, `perl`), downloads of the new
release's source, `curl`, an `rm` given as an absolute path. Each agent then used the file tools or the web tools; none
of the denials stopped a session, unlike DT-QA-05's report that couldn't be read. Read-only commands (`grep`) ran in B's
shell under `dontAsk`, as in DT-QA-05; A had no shell.

**Scoring corrections made after the first scored pass, before this summary** (all in `score.py`, each making it do
what README.md says; the first pass read A 69.7% and B 72.7% sessions fixed, 4 and 3 sessions with a new break, and
76.0% and 81.5% of confirmed breaks fixed):

1. a file whose name holds non-ASCII bytes (a Streamlit page named with an emoji) is quoted in a git diff; the parser
   crashed on it before any score;
2. a module of another package under a shared namespace (`llama_index.llms.langchain`, `llama_index.llms.openai` in a
   llama-index-core environment) failed in the probe only because the environment doesn't install it. DT-QA-05's first
   correction meant to make that `can't tell`, but compared only the top-level name and only "No module named"; it now
   compares dotted names and also reads the probe's "module 'llama_index' has no attribute 'llms'". It took one new break
   off each arm, in one task both arms already failed;
3. Poetry's bare exact pin (`langchain = "1.4.9"`, the version `to` names) was read as pinning away from `to`. A's
   session on nl2sql-studio became `can't tell` and was hand-checked: still not fixed (below). A's confirmed breaks
   fixed rose from 288 to 297, and its sessions with a new break from 3 back to 4.

Re-scoring DT-QA-05 from its probe output with the corrected `score.py` reproduces its committed tables unchanged.

**Hand checks:** 147 uses (144 work, 3 break) and 42 breaks (all fixed), each with the released source file and line
(`hand-checks.json`). The 136 uses and 42 breaks found first were checked from the blinded file and from each session's
diff printed by check id. The last 11 uses, all from A's nl2sql-studio session, were not blind: correction 3 surfaced
them after its verdict line was read. Among them is the call this report counts against A there:
langchain-google-vertexai 3.2.5's `VertexAIEmbeddings()` binds but raises "model_name must be provided" at construction,
where langchain 0.1's had a default model. Read as binding only, that session is fixed and A reads 47 of 66 (71.2%);
the bar's verdict is the same either way.

**What it means for DepTime.** The bar's first line is missed, so per README.md DT-OSS-17 leaves the command and the
report's agent block out of what 1.0 freezes, marks both experimental, and the plugin's README leads with asking the
agent in plain words. The rest of the result is better than that rule reads: the reworked hand-off now matches the
agent alone on success, wins on breaks fixed, new breaks and cost, and loses only where it tells the agent to stop. The
one clear fault is step 3's "leave the line"; DepTime's own gap here is DT-CORE-34.

**Note added after the result (2026-11-16).** The streamlit miss above is not DT-CORE-34: `check_symbols` already
checks required arguments. Since streamlit 1.33, `st.pyplot` and 102 other top-level names are bound through an
annotated module-level instance (`_main: _DeltaGenerator = ...`), which the index read as attributes with no
signature, so their calls went unchecked. Fixed as DT-DATA-83 (`SNAPSHOT_FORMAT` 28); the maintainer chose to fix
both causes and measure again on new updates (DT-QA-27) before 1.0.

**Limits.** 66 small projects with no tests the agent could run; one model; one run per arm, so a task's two sessions
are the only pair. "Fixed" means the new code resolves and binds at `to` (and, for the call above, constructs), not
that the program behaves as before. DepTime's answers on these sets are in-sample.
